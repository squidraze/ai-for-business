# CRM и учётные системы в Узбекистане: исследование

Дата: 24 ноября 2026. Для кого: Сардор и Асад. Зачем: решить, какие системы подключать к forBusiness и в каком порядке.

## Главное

- **Независимой статистики по рынку нет.** Почти все цифры о клиентах дают сами вендоры, и обычно по всему региону (Казахстан, Узбекистан, Кыргызстан, Таджикистан), а не только по Узбекистану. Это ориентир, а не факт.
- **«CRM в каждом магазине» — это чаще касса с учётом товаров, а не CRM.** С 2025 года все торговые точки обязаны отправлять чеки через ОФД, поэтому почти у всех появилась программа с фискализацией. Для ИИ это другие данные: продажи, остатки, чеки, клиенты и долги, а не сделки и воронки.
- **Рынок раздроблен:** в обзорах только для магазинов перечисляют 20–25 программ. Явного лидера нет.
- **Классические CRM:** Bitrix24 — около 60% сайтов в Узбекистане, amoCRM — около 19% (оценка WMTips по сайтам, а не по компаниям).
- **Первая волна интеграций:** BILLZ, МойСклад, REGOS, Bitrix24, amoCRM/Kommo, Paloma365. План: [../plans/crm-integrations-plan.md](../plans/crm-integrations-plan.md).

## Таблица 2. Сложность подключения и подводные камни

| Система | Сложность | Лимиты API | Что важно |
|---|---|---|---|
| BILLZ | 🟢 низкая | в документации не указаны (есть ответ 429) | Ключ меняют на пару токенов: access на 15 дней, refresh на 30 дней. Refresh одноразовый: повторное использование отзывает всю сессию. Вебхуков нет. Создание продажи асинхронное. Есть продажи, остатки, клиенты, долги, кэшбэк и отчёты, включая выгрузку в Excel. |
| МойСклад | 🟢 низкая | ~45 запросов за 3 с на аккаунт, 5 параллельных на пользователя (по данным SDK; официальную страницу прочитать не удалось) | Это учёт, а не CRM. На тарифах «Бесплатный» и «Старт» есть ограничения. Свой маркетплейс приложений тоже есть: для него нужно юрлицо в РФ или СНГ и рублёвый счёт, МойСклад оставляет себе 25% от цены нашего приложения. Если клиент сам вставляет токен из своего аккаунта, маркетплейс не нужен и комиссии нет. |
| REGOS | 🟡 средняя | 2 запроса в секунду, запас 50, на каждую интеграцию | Ключ интеграции передаётся в URL. Ошибки приходят с HTTP 200 внутри `result`. Вебхуки заявлены. Подходит ли их OAuth для сервиса со многими клиентами — надо спросить у REGOS. |
| Bitrix24 | 🟡 средняя | 2 запроса в секунду, запас 50 (на Enterprise 5 и 250) | Вебхук неудобен клиенту и даёт все права пользователя, поэтому для прода нужен OAuth. При перегрузке бывает блокировка `OVERLOAD_LIMIT`, снимает её только поддержка. |
| amoCRM / Kommo | 🟡 средняя | 7 запросов в секунду, блокировка по IP | Две раздельные площадки (amocrm.ru и kommo.com), это надо проверить. Модерация 1–2 рабочих дня. Refresh-токен отзывается после 3 месяцев без использования. |
| Paloma365 | 🟡 средняя | цифр нет («при спаме ограничения») | Нужен договор. API включают по странам: пока выключен, запросы получают 404, поэтому надо проверить Узбекистан. |
| Poster | 🟡 средняя | не проверено | Это общепит. Детали авторизации проверить не удалось. |
| UMAG | 🔴 | — | Крупнейший по заявленным цифрам, без API. Только партнёрство. |
| Smartup, Sales Doctor | 🔴 | у Smartup дневной лимит | Это B2B-дистрибуция, не наша аудитория. |
| MDokon | 🔴 | — | Нет API. |
| 1С | 🔴 очень высокая | — | У каждого своя конфигурация и база, нужна публикация на веб-сервере. |

## Paloma365: сколько клиентов в Узбекистане (оценка)

Цифры по Узбекистану Paloma365 не публикует. Что известно:

| Дата | Данные | Источник |
|---|---|---|
| февраль 2020 | 6000+ точек в KZ, RU, UA, KG, BY, **Узбекистана в списке нет** | Forbes.kz |
| ноябрь 2024 | 10 000+ компаний, у каждой 1–10 точек; главные рынки — «Казахстан, Узбекистан и США» | Kapital.kz |
| сейчас | 20 000+ точек, без разбивки по странам | paloma365.uz |

Признаки работы в Узбекистане: цены в сумах (от 134 700 сум в месяц), интеграции с UZKASSA, e-POS, QPos и ОФД, ташкентский телефон, отзывы из Ташкента, Самарканда, Бухары. Отдельного офиса в Узбекистане нет: в подвале сайта казахстанский БИН, офис в Алматы.

Как считали: прирост с 2020 года — около 14 000 точек, в основном на двух главных рынках. На Узбекистан мы отнесли 25–45% прироста. В среднем 1,5–2 точки на клиента.

| Сценарий | Точек в UZ | Клиентов в UZ |
|---|---|---|
| пессимистичный | ~1500 | ~800–1000 |
| **реалистичный** | **~3000–5000** | **~2000–3000** |
| оптимистичный | ~7000 | ~4000 |

Уверенность низкая. Настоящую цифру проще всего спросить у Paloma365 на переговорах о договоре.

## Что ещё популярно и подключается легко (следующая волна)

| Система | Почему стоит | API | Подвох |
|---|---|---|---|
| **Uzum Market (кабинет продавца)** | главный маркетплейс Узбекистана, многие наши пользователи продают там | токен создаётся в кабинете продавца (seller.uzum.uz → Настройки → API), по сторонним данным | официальную документацию не нашли, нужно проверить; это маркетплейс, а не CRM |
| **Poster** | 23 000 заведений, есть фискализация для UZ (Multikassa) | ✅ открытый API и маркетплейс | если продаём через маркетплейс Poster, он оставляет себе 30% от цены нашего приложения. Можно ли подключаться по токену клиента без маркетплейса (и без комиссии), не проверили |
| **iiko** | популярная касса для ресторанов | ✅ iikoCloud API, ключ из iikoWeb (по сторонним данным) | только общепит; сверить с официальной документацией |
| **RetailCRM** | CRM для интернет-магазинов, BILLZ с ней интегрирован | ✅ ключ API клиент создаёт сам | лимит «10 запросов в секунду с одного IP». У каждого клиента своя система на своём адресе, поэтому лимит, скорее всего, считается отдельно для каждого клиента, но это надо проверить |
| **Google Sheets** | многие малые бизнесы ведут клиентов в таблицах | ✅ Google API, у нас уже есть Google OAuth | нужна проверка OAuth-приложения Google по нужным scope |

Потом: UMAG (после переговоров), 1С (через франчайзи), Smartup и Sales Doctor (если появятся дистрибьюторы среди клиентов).

## Что сделать до решения

1. **Опрос (Асад):** 30–50 магазинов и кафе из нашей аудитории. Вопросы: что стоит на кассе и чем ведёте клиентов. После этого порядок интеграций будет опираться на факт.
2. **Переговоры (Асад):** Paloma365 (договор на API, включён ли API для UZ, сколько клиентов в UZ), UMAG (есть ли закрытый API или партнёрская программа).
3. **Перед реализацией (Сардор):** сверить лимиты и авторизацию по официальной документации каждой системы. Где в таблицах написано «по данным SDK» или «сторонние данные», мы ещё не проверили.
