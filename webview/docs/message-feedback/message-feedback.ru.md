# Оценка ответа: палец — это хранимый объект

English version: [message-feedback.md](message-feedback.md).

Пальцы под ответом ассистента однажды уже убрали из этого приложения — осознанно:
за ними не было эндпоинта, голос не доходил до бэкенда и ничего не переживал, а
контрол, который молча ничего не делает, хуже отсутствия контрола. С
**05.09.2026** эндпоинт есть, поэтому кнопки вернулись — уже подключёнными.

```
POST /api/v1/ai/conversations/{conversation_uuid}/messages/{message_uuid}/feedback
     { "rating": "good" | "bad" | null, "comment"?: "…" }
  →  { message_uuid, feedback_rating, feedback_comment }
```

## Что гарантирует бэкенд и что из этого следует

- **Оценка сначала пишется в строку сообщения** и только потом уходит в Langfuse
  как score на трейс, из которого вышел ответ. Падение Langfuse стоит score, но
  никогда не стоит оценки и не роняет запрос — поэтому на клиенте нет ни особой
  логики повторов, ни второго источника правды, который пришлось бы сверять.
- **`AIMessageRead` её возвращает** (`feedback_rating`, `feedback_comment`) — и
  только поэтому оценку вообще можно восстановить: открыв тред завтра, видишь тот
  же залитый значок.
- **`rating: null` снимает оценку.** Это вторая половина тумблера, а не третье
  состояние: нажатие на уже залитый палец отправляет `null`. Мнение, которое
  нельзя забрать назад, — это свой собственный вид сломанного контрола.
- **Ответ, написанный до миграции, отвечает `422`, и будет отвечать всегда** — у
  него нет трейса, на который вешать score. Это ответ, а не сбой: показываем
  **информационный** тост именно с такой формулировкой, никогда не как ошибку с
  повтором, и логируем на `info`, а не на `warn`.

## Как это собрано здесь

| Часть | За что отвечает |
| --- | --- |
| `lib/api/ai.ts` → `submitMessageFeedback` | сам вызов; формы запроса/ответа — в `lib/api/types.ts` |
| `chat/feedback.ts` → `rateMessage` | тумблер, оптимистичное обновление и откат |
| `chat/types.ts` → `AssistantMessage.feedback` | оценка на самом сообщении — без бокового стора, потому что у этого приложения своя модель сообщений |
| `chat/history.ts` | сужает `feedback_rating` на собранный ход |
| `ui/chat/MessageActions.tsx` | два значка, залитых, а не просто подкрашенных |

**Оценка живёт на сообщении, а не в кэше рядом.** Нативному чату нужен боковой
стор по uuid (assistant-ui негде хранить оценку); здесь свой стор, поэтому поле
лежит там же, где ответ, а оптимистичное обновление — обычный
`updateAssistantMessage`.

**Один ход хранится несколькими строками, и оценка стоит на той, что была на
экране в момент нажатия.** `toTranscript` сворачивает эти строки в один пузырь,
поэтому при свёртке берётся первая найденная оценка по всему ходу, а не (обычно
пустое) значение последней строки. Иначе ответ, оценённый вживую — где uuid
приходит из `ai.run.completed`, — вернулся бы из истории без оценки.

**Ни спиннера, ни поля для комментария.** Оценка не стоит состояния загрузки:
значок заливается по нажатию и откатывается, если запрос упал. API принимает
необязательный `comment` (2000 символов), и клиентская обёртка его пробрасывает,
но UI под него пока нет — «что именно не так?» это вопрос дизайна, а не проводки.

## Как проверить

Без бэкенда — `npm run dev`, откройте **Thread with history** из DEV-панели:

| Действие | Ожидание |
| --- | --- |
| Посмотреть на первый ответ | палец вверх уже залит — пришёл из `feedback_rating` фикстуры |
| Нажать палец вниз на любом ответе | он заливается, верхний гаснет |
| Нажать залитый палец ещё раз | он гаснет (в эфире это `rating: null`) |
| Перезагрузить тред из DEV-панели | все оценки на месте — мок хранит их в строке, как и бэкенд |
| Оценить последний ответ («…so rating it answers 422») | палец заливается, откатывается, показывается информационный тост: ответ старше самой функции |
| Отправить сообщение и оценить ответ сразу после завершения | работает — ответ узнал свой uuid из `ai.run.completed` |

На реальном бэкенде смотреть строки лога `rating saved` и `this reply predates
feedback and cannot be rated`.
