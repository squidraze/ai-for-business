# Паритет с AI-чатом веб-клиента

English version: [web-parity.md](web-parity.md).

У этого ассистента есть чат и в веб-приложении (`rooler_apps`,
`apps/web/widgets/deep-agent-chat`). 2026-10-23 этот экран подтянули до него.
Здесь записано, что перенесено, откуда взято каждое правило и что намеренно
оставлено. Прочитай это, прежде чем что-то из этого менять: оба клиента должны
отвечать одному и тому же человеку одинаково.

Собственный гайд веба — `docs/guides/deep-agent-api.md` в `rooler_apps`. Это самое
точное описание контракта бэкенда, общего для обоих клиентов.

## Правила, которые стоит знать до правок

**Стоячее разрешение предлагается, только если его принимает каждый инструмент
карточки.** Инструменты карточки — это ключи `allow_options`, а не названия в её
строках: строка connected app называет внутреннее действие, а ключ — тот
инструмент, на который бэкенд записывает разрешение. Нативный экран использует то
же правило (`toolPermissions.utils.ts`).

**Подключённый run без uuid следует за разговором.** Run на паузе одобрения не
всегда есть в `GET …/runs`, а в `GET …/pending` нет uuid run. Поэтому стрим
восстановленной карточки подхватывает первый run этого разговора, который
заговорит. После решения это `ai.run.resumed` того самого run, который ждали
(`StreamJoinOptions` в `realtime/aiEvents.ts`).

**Подключённый run видит только хвост своего ответа.** Когда он заканчивается,
история перечитывается, но заменяет экран, только когда в ней есть uuid этого
ответа из `ai.run.completed`. До тех пор история перечитывается несколько раз, а
потом на экране остаётся то, что пришло стримом. Слепая замена могла бы подменить
ответ, который пользователь только что видел, тредом, оканчивающимся его вопросом.

**Вызов инструмента — не part.** Строка «Used N tools» и список задач идут рядом с
частями, как рассуждения модели. Они стоят над ответом целиком. Три вызова никогда
не становятся карточками, потому что рисуют своё: `render_ui` (представление),
`task` (карточка делегирования) и `write_todos` (список задач).

**Ошибку инструмента распознаём по форме, флага нет.** На проводе флага нет.
Распознаются три формы: `Tool 'x' failed: …`, `Chart 'x' failed to run: …` и
`{error}` / `{is_error: true}`. У первых двух нет общего префикса (`backend-issues`
§8), поэтому проверка, написанная под одну, молча пропускает другую. Результат
решает только чип на карточке и ничего больше.

**Сообщение, написанное во время ответа, ждёт.** Если его отправить, оно повиснет
на том же родителе, что и идущий ответ, и разговор разветвится. Поэтому оно ждёт в
памяти, только для текущего треда. «Send now» останавливает ответ и ждёт секунду
перед отправкой: run, запущенный в момент отмены другого, может зависнуть на
бэкенде. На телефоне Enter — это перенос строки, поэтому, пока идёт ответ и что-то
набрано, рядом со Stop стоит кнопка Send.

**Connectors — один переключатель на приложение, PATCH всегда всего списка.** В
новом чате список ждёт первого сообщения (`disabled_connectors` в
`POST /ai/messages`). Последний выбор запоминается под ключом `localStorage` веб-клиента. «Add / Manage
connectors» открывает нативный лист Integrations хоста (`open.integrations`):
подключение приложения — это OAuth в системном браузере.

**Роль и права берутся из `GET /auth/me/context`** — из membership компании, которая
пришла в `init`. Если чтение не удалось, видны все подсказки: так же веб ведёт себя,
пока авторизация не разрешилась.

## Намеренно не перенесено

- **Сырой recharts в сгенерированных представлениях.** Белый список веба
  пропускает ещё `AreaChart`, `XAxis`, `ResponsiveContainer` и другие примитивы
  recharts, а также `StatTrendCard`. Они нужны для артефактов от shadcn
  MCP-сервера (`source_tool: "shadcn"`), а не для `render_ui`. Словарь, который
  бэкенд опубликовал для `render_ui`, — плоские `BarChart` / `LineChart` /
  `PieChart` (`{title, unit, data}`), и это приложение их уже рисует. recharts
  добавил бы сотни КБ в бандл, который и так превышает бюджет.
- **Рассуждения только в debug.** Веб показывает `ai.reasoning` только с
  `?debug=true`. Здесь они, как и раньше, видны всем под точками набора.
- **Начать чат с кастомным агентом.** В приложении нет экрана агентов, откуда его
  начать. Открыть разговор, у которого агент уже есть, можно.
- **Настройки голоса и кнопка диктовки** относятся к нативному голосовому экрану,
  а не к этой странице.
- **Чего нет и в вебе:** экрана прав на инструменты (в нативном приложении он
  есть), inbox автономных агентов, переименования разговора и подгрузки старых
  страниц истории.

## Как проверить

У всего перечисленного есть slash-команда в мок-бэкенде (см. README), и всё
прогнано против мока в headless Chrome при 390×844, в обеих темах. На устройстве и
против реального бэкенда это ещё не запускалось.
