# Размышления и делегирование: два события, которых раньше не было в эфире

English version: [thinking-and-delegation.md](thinking-and-delegation.md).

**05.09.2026** бэкенд включил две вещи, которые контракт стриминга описывал
всегда, но никогда не присылал:

- **`ai.reasoning`** теперь приходит на любом текстовом ходе (кроме голоса —
  размышления добавляют задержку, которую живой звонок себе позволить не может).
- **`ai.tool_call.args`** теперь несёт настоящие, полные аргументы модели
  (раньше всегда `null`), а вместе с ними — **`tool_call_id`**, то же поле, что
  и у `ai.tool_result`. Значит, вызов можно сопоставить со своим результатом, а
  не угадывать по имени инструмента.

Оба обработаны здесь. Ниже — что они означают для экрана и что сознательно
сделано **не** было.

---

## 1. Размышления (`ai.reasoning`)

Некоторые модели проговаривают план до ответа. Тогда дельты приходят отдельным
потоком, батчами как `ai.token`, **до первого `ai.token`** и никогда не
вклиниваются после начала текста. Размышления есть не на каждом ходе — модель
или ход, который «не думает», просто ничего не пришлёт, поэтому ждать первой
дельты нельзя.

**Это только «живое», и в этом всё ограничение дизайна.** Бэкенд ничего из
этого не хранит: `ai.run.completed.content` их не содержит, и получить их потом
неоткуда. Отсюда:

| Решение                                                    | Почему                                                                                                             |
| ----------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------- |
| Едет в `AiRunChunk.reasoning`, **не** как часть (`part`)   | `MessagePart` — это контент: его скопируют, перегенерируют, свернут в историю — и он исчезнет при следующем открытии |
| Живёт в `AssistantMessage.reasoning`                       | Рядом с ходом, чтобы код, который обходит `parts`, не подхватил его случайно                                        |
| Рисуется, только пока в ходе нет текста                    | Правило самого контракта: на первом `ai.token` переключаемся на обычный вид ответа                                  |
| Показывается только хвост, две строки, с растворением сверху | Размышления занимают абзацы и не являются ответом                                                                  |

Компонент — `ThinkingTrace`; `AssistantMessage` монтирует его под точками
«печатает», и оба уходят вместе с первым токеном.

## 2. Делегирование (инструмент `task`)

В эфире модель не «порождает субагента» — она вызывает инструмент, который так и
называется, `task`, с аргументами `{ subagent_type, description }`:

```jsonc
{ "event_type": "ai.tool_call", "run_uuid": "…", "seq": 4,
  "data": { "tool": "task", "tool_call_id": "call_…",
            "args": { "subagent_type": "code-runner",
                      "description": "Build an xlsx report of August work orders" } } }
```

Это рисуется карточкой сразу по приходе и закрывается парным `ai.tool_result` —
сопоставление по `tool_call_id`, с откатом на порядок прихода, если у результата
id нет.

**Между ними по замыслу нет ничего.** Что субагент делает внутри — запускает
код, читает и пишет файлы — для этого канала непрозрачно. Поэтому карточка — это
одно состояние «ждём → готово», а не список шагов: список оставил бы на экране
вечно недоделанный чеклист.

Три состояния, потому что событий всего два плюс завершение рана:

| Состояние | Когда                                                                          |
| --------- | -------------------------------------------------------------------------------- |
| `running` | вызов пришёл, ответа ещё нет                                                     |
| `done`    | `ai.tool_result` пришёл и не читается как ошибка                                 |
| `failed`  | результат читается как ошибка **или** поток закончился, а результат так и не пришёл |

Последний случай не гипотетический: зависший `task`, утаскивающий за собой весь
ран, — живой баг бэкенда (см.
[backend-issues §2](../backend-issues/backend-issues.ru.md)), а крутящаяся
карточка утверждала бы, что субагент ещё работает, когда его уже никто не
слушает. `streamAiRun` закрывает все открытые делегирования на конце потока:
`done`, если ран завершился, `failed` — если упал, завис или был остановлен.

**При повторном открытии треда карточка возвращается.** Вызов хранится в
`tool_calls` ассистентской строки (формат OpenAI: `{ id, function: { name,
arguments } }`, аргументы — JSON-строка), а ответ — отдельной строкой с ролью
`tool`. `toTranscript` читает обе (предпроход индексирует результаты, потому что
строка-ответ идёт **после** своего вызова), так что ожидание, определившее ход,
переживает перезагрузку. Делегирование **без** сохранённого результата
возвращается как `failed` — по той же причине, что выше.

Всё, кроме `task` и `render_ui`, по-прежнему не рисуется: такие вызовы — это
модель, добирающая контекст, и именно part на каждый из них когда-то вставлял в
ход невидимый блок и писал «unknown generative-UI tool» на каждый рендер.

## 3. Что сознательно не менялось

- **Предложение выгрузить в Excel.** Показав данные, которые естественно легли
  бы в таблицу, модель теперь сама предлагает выгрузку словами вместо того,
  чтобы строить файл без спроса. Это обычный текст ответа в `ai.token` — ни
  нового события, ни работы на клиенте.
- **`ai.step`** по-прежнему зарезервировано и не приходит. Обработчик для
  несуществующего события не добавлялся.
- **`args` остаётся опциональным.** Вызов с оборванным потоком аргументов всё
  ещё приходит с `args: null`, поэтому каждое чтение защитное.

## 4. Как проверить

Совсем без бэкенда — `npm run dev`, затем в поле ввода:

| Ввести       | Ожидать                                                                                                              |
| ------------ | ---------------------------------------------------------------------------------------------------------------------- |
| `/think`     | точки, под ними бегущий текст размышлений, и то и другое сменяется ответом на первом токене                          |
| `/task`      | короткая мысль, строка текста, карточка **Delegating to code-runner**, которая крутится ~1,8 с и становится **Done**  |
| `/task hang` | та же карточка, всё ещё крутится — через 60 с сторожевого таймера станет **Didn't finish**, ход помечен прерванным     |

Затем откройте тред заново из DEV-панели: карточка делегирования возвращается
закрытой, размышления не возвращаются вовсе. И то и другое — правильно.

На реальном бэкенде смотреть в логи: `ai.tool_call — delegating to a subagent`,
`a delegation came back` (там указано, сопоставилось по `tool_call_id` или по
порядку прихода) и `run stream ended`, где `reasoningChars` и
`unresolvedDelegations` говорят, что ход на самом деле получил.
